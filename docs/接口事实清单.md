# 麦当劳 MCP 接口事实清单（实测）

> 全部来自 2026-10-21 对 `https://mcp.mcd.cn` 的真实调用，非文档转述。
> 官方文档（M-China/mcd-mcp-server README）只有 33 个工具名和一句描述，
> 没有入参 schema，且部分内容已过时。以下为实测校正。

---

## 1. 工具数量：35 个，不是文档说的 33 个

文档未收录，但真实存在：

| 工具 | 用途 |
|---|---|
| `query-promotions` | 查询活动 |
| `query-survey-coupon` | 按订单号查满意度答卷及关联奖券 |

**文档拼写错误（照抄会直接失败）**：

| 文档写的 | 实际是 |
|---|---|
| `query-partystore-date` | `query-party-store-date` |
| `query-partystore-session` | `query-party-store-session` |

正确工具清单可通过 `python scripts/probe.py schema` 取回。

---

## 2. 响应格式：Markdown 文档包 JSON

**这是最容易踩的坑**：MCP 返回的 `content[].text` 不是 JSON，而是一份给 LLM 看的文档：

```
每个门店的基本信息按单行展示：        <- 展示指令
- **门店名称**: data[].storeName
...
{"success":true,"code":200,...,"data":{...}}   <- 真正的 JSON，位置不固定
```

三种形态都遇到过：

1. 有 `## Original Response` 标记，JSON 在标记之后
2. **没有标记，JSON 直接跟在展示指令后面**（更常见）
3. `data` 本身是 Markdown 文本（如 `query-my-coupons` 返回「# 您的优惠券列表」）

所以**不能用 split 或固定标记定位**，必须做括号平衡扫描。见 `mcp_client._scan_json_object`。

### 信封结构

```json
{
  "success": true,
  "code": 200,
  "message": "请求成功",
  "datetime": "2026-10-21 22:59:46",
  "traceId": "9dd4e0b5...",
  "data": { }
}
```

`success:false` 时 `message` 是中文原因，`traceId` 可用于追溯。

---

## 3. 会话：无状态

`initialize` 成功但**不返回 `Mcp-Session-Id`**（返回「无状态会话」）。
因此不要依赖会话头，每次请求都是独立的。

---

## 4. 实测错误码

| code | message | 触发条件 |
|---|---|---|
| `600058` | 城市名或者关键词不能为空 | `query-nearby-stores` 只传了 city 或只传 keyword |
| `600057` | 门店可能已关闭或不在营业时间 | 对非营业门店调 `query-meals` |

业务错误由 `mcp_client.call_tool_data` 自动识别并抛出，含 traceId。

---

## 5. 关键隐含约束（文档未写）

### `query-nearby-stores` 的 city 与 keyword 必须同时传

```python
# 都会报 600058
{'beType':1,'searchType':2,'city':'上海'}
{'beType':1,'searchType':2,'keyword':'上海'}

# 只有这样才能成功
{'beType':1,'searchType':2,'city':'上海','keyword':'上海'}
```

### 外送场景 `beCode` 必传

`beCode` 在入参里标记为「选填」，但描述写明：
> 得来速(beType=5)/外送(orderType=2)/团餐场景必传，到店自取(beType=1)场景不传

照入参 schema 的必填标记去传，外送会失败。

### 门店必须先判断营业状态

`query-nearby-stores` 返回 `businessStatus` 字段。
深夜实测 5 家门店只有 1 家 `true`，对 `false` 的店调 `query-meals` 会报 600057。
**选店要先按 `businessStatus` 过滤。**

---

## 6. 核心枚举值

| 参数 | 值 |
|---|---|
| `beType` | 1-到店取餐，2-麦乐送到家，5-得来速(DT)，6-企业团餐 |
| `orderType` | 1-到店（含到店自取+得来速），2-外送（含麦乐送+团餐） |
| `searchType` | 1-搜索收藏餐厅，2-按位置搜索 |

## 7. 菜单数据结构（`query-meals`）

```json
{
  "categories": [
    {"name": "人气热卖", "meals": [{"code": "9900016076", "tags": ["心形薯饼同款比心"]}]}
  ],
  "meals": {
    "511781": {
      "name": "培根安格斯厚牛堡",
      "image": "https://menu-img.mcd.cn/...",
      "currentPrice": "34.5",
      "originalPrice": "34.5",
      "canWithOrder": false
    }
  }
}
```

要点：

- `categories` 有 15 个分类，`meals` 字典含 114 个菜品（单店）
- **`currentPrice` 是字符串，单位是「元」**（`calculate-price` 返回的是「分」，混用会差 100 倍）
- `categories[].meals[].code` 就是 `productCode`，直接用于 `calculate-price` 与 `create-order` 的 `items[].productCode`
- 分类名可直接用于组单：巨无霸/牛鱼肉堡、安格斯MAX厚牛堡（主食）；小食甜品/其他（小食）；麦咖啡、饮品（饮料）

## 8. 完整外送链路（含实测参数）

```
now-time-info                                          无参
delivery-query-addresses                               无参 → addressId
delivery-create-address                               address, addressDetail, city,
                                                      contactName, phone(11位), gender
delivery-query-stores    {addressId, beType:2}         → storeCode, beCode
query-meals              {storeCode, beCode, beType:2, orderType:2}
query-store-coupons      {storeCode, beCode, beType:2, orderType:2}
query-my-coupons         {page?, pageSize?}
calculate-price          {storeCode, beCode, beType:2, orderType:2,
                          items:[{productCode, quantity, couponCode?, couponId?}]}
create-order             {storeCode, beCode, beType:2, orderType:2, addressId,
                          items:[...], needTableware?, remark?(≤50字)}
query-order              {orderId}
```

`create-order` 的 `takeWayCode`：到店场景必传，**外送/团餐场景不传**。

## 9. 复现方式

```bash
export MCD_MCP_TOKEN=...
python scripts/probe.py schema      # 取回 35 个工具的 inputSchema
python scripts/probe.py readonly    # 跑只读链路
```
